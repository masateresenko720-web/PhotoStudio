# Фотостудия — Windows и Microsoft SQL Server

## Что подготовлено и что проверено

В комплекте исходный проект C# / Avalonia / EF Core, готовая сборка win-x64, SQL-скрипты структуры и данных, проверки и инструкция. SQLite не используется. Сохранены исходная ER-диаграмма и все её 7 таблиц, 31 столбец и 7 внешних ключей.

Сборка и серверные проверки выполнены на Linux. На SQL Server 2025 Developer 17.0.5035.5 пройдены все 36 сценариев, включая запись заказов, роли, транзакции, два процесса и 12 снимков настоящих форм с SQL-базой. Результаты находятся в `evidence-sql`. Создана настоящая копия базы `database/backup/PhotoStudio_SQLServer2025.bak`, выполнен RESTORE VERIFYONLY. Дополнительно пройдены 18 локальных проверок; их снимки в `evidence-offline` относятся к данным в памяти. EXE Windows x64 опубликованы, но именно в Windows здесь не запускались: повторите `windows/VERIFY_SQL_SERVER.bat` на своём компьютере.

**Начните с QUICK_START_RU.md и START_HERE.bat.** В программу добавлено окно настройки SQL Server. Успешное подключение сохраняется в `%LOCALAPPDATA%\PhotoStudio\connection.json` и используется EXE, Visual Studio и проверками. При наличии этого файла он имеет приоритет над appsettings.json; переменная PHOTOSTUDIO_CONNECTION имеет ещё больший приоритет.

## 1. Установка на Windows

1. Используйте Windows 10/11 x64, для учебного стенда рекомендуется Windows 11 x64, 8 Гбайт ОЗУ и 3 Гбайт свободного места плюс место для SQL Server.
2. Установите SQL Server 2025 Developer по методичке либо используйте установленный SQL Server 2022 Developer/Express. Developer предназначен для разработки и обучения, не для рабочей эксплуатации. Сайт: https://www.microsoft.com/en-us/sql-server/sql-server-downloads .
3. В мастере выберите Database Engine Services, вход Windows Authentication. Добавьте текущего пользователя в администраторы SQL Server. Запишите имя экземпляра. Для экземпляра по умолчанию это `localhost`; для именованного Express часто `.\SQLEXPRESS`.
4. Установите SSMS: https://learn.microsoft.com/en-us/ssms/install/install . SSMS — программа управления; её установка сама по себе не устанавливает сервер.
5. Распакуйте весь комплект в `C:\Coursework\PhotoStudio`. Не запускайте EXE внутри ZIP.
6. Для готовой сборки .NET отдельно не нужен. Для изменения кода установите Visual Studio 2026 Community с нагрузкой «Разработка классических приложений .NET» и .NET 10 SDK: https://dotnet.microsoft.com/download/dotnet/10.0 .

## 2. Подключение и создание базы

1. Проверьте подключение в SSMS: Server name — имя вашего экземпляра; Authentication — Windows Authentication. Локально при ошибке учебного сертификата отметьте Trust server certificate.
2. Запустите START_HERE.bat и укажите имя сервера из SSMS в окне настройки. Нажмите «Создать / проверить базу и войти». Для ручной настройки без сохранённого профиля можно изменить windows/app/appsettings.json.
3. По умолчанию: `Server=localhost;Database=PhotoStudio;Integrated Security=True;Encrypt=True;TrustServerCertificate=True;Connect Timeout=10`.
4. В JSON обратную косую черту нужно удвоить: для Express строка начинается `Server=.\\SQLEXPRESS;...`. Полный пример есть в `docs/connection-express.json`.
5. Запустите `windows/SETUP_DATABASE.bat`. Он создаёт базу PhotoStudio с русской кодировкой и выполняет `01_StructureAndSeed.sql`. Если в базе уже есть таблицы, они не удаляются: проверяется их соответствие исходной схеме.
6. Если существующая PhotoStudio создана старой версией и имеет другие поля, не удаляйте её ради запуска. В окне настройки замените имя базы либо в JSON замените `Database=PhotoStudio` на новое имя, например `Database=PhotoStudioER`, и снова запустите настройку.
7. После успешной настройки нажмите Refresh в SSMS → Databases. В новой базе раскройте Tables. Там должны быть `roles`, `users`, `halls`, `orders`, `statuses`, `services`, `order_services`.
8. Выполните в SSMS файл `database/02_Checks.sql`. До регистрации и новых заказов ожидается: 3 роли, 4 статуса, 10 пользователей, 4 зала, 4 услуги, 15 заказов и 15 строк услуг.

### Ручное создание вместо BAT

Откройте `database/00_CreateDatabase.sql` в SSMS и выполните целиком. Затем выберите PhotoStudio в выпадающем списке баз и выполните целиком `database/01_StructureAndSeed.sql`. Скрипт предназначен только для пустой базы и отклоняет повторный запуск. `GO` применяется только в первом скрипте. Основной скрипт выполняет создание и заполнение в одной транзакции. Не запускайте его по отдельным выделенным строкам.

## 3. Запуск и учётные записи

Откройте `windows/START.bat`. На экране входа можно открыть гостевой каталог или зарегистрироваться. Демонстрационные логины: `admin` — администратор, `photo1`, `photo2` — фотографы, `client1`–`client7` — клиенты. Пароль всех учебных записей: `PhotoStudio!2026`. Пароли в SQL-скрипте хэшированы с отдельной случайной солью; это не открытые пароли.

- Гость: поиск залов по названию/описанию, максимальной цене и свободному времени; сортировка; карточка зала; регистрация.
- Клиент: выбрать зал → «Войти для бронирования» / «Забронировать» → будущая дата, время, фотограф при необходимости, количество услуг → «Рассчитать стоимость» → «Сохранить бронирование». В заказах видны только свои записи.
- Отмена: открыть свою активную запись → поставить флажок подтверждения → «Отменить бронь». До начала должно оставаться не менее 24 часов.
- Администратор: открыть заказы → карточку → при необходимости назначить свободного фотографа. После получения оплаты поставить флажок «Оплата получена» и подтвердить бронь. Справочники и отчёт доступны из меню.
- Фотограф: открыть «Мои съёмки», выбрать назначенный заказ. Завершить подтверждённую съёмку можно после её окончания.

Время локальное для компьютера фотостудии. Дата вводится `ГГГГ-ММ-ДД`, время `ЧЧ:ММ`. Рабочие часы 09:00–22:00, шаг 30 минут, один календарный день. Будни ×1,00, выходные ×1,20, после 18:00 дополнительно ×1,15. Брони «Новый» и «Подтверждён» занимают зал и фотографа. Соседние интервалы допустимы.

## 4. Как сохранена исходная ER-диаграмма

Ни одной дополнительной таблицы или колонки нет. Нельзя одновременно оставить диаграмму неизменной и хранить в ней отсутствующие данные. Поэтому:

- `total_price` из описания 2.1 трактуется как вычисляемое свойство Total в C#, а не столбец SQL. Значение вычисляется по залу, интервалу и выбранным услугам.
- Точная сумма предоплаты не хранится: статус «Подтверждён» фиксирует, что администратор подтвердил факт получения оплаты. Сумма и документы платежа учитываются вне программы; отдельного платёжного журнала в диаграмме нет.
- Чтобы старые суммы не изменились, цену использованного зала/услуги программа не разрешает менять. Для нового тарифа администратор создаёт новую запись справочника. Название и описание можно редактировать. Прямое изменение цены в SSMS обходит эту защиту, поэтому не делайте его для использованных записей.
- Типы `varchar`, длины, `text`, `date`, `datetime` сохранены по диаграмме. База создаётся с `Cyrillic_General_100_CI_AS`. Для decimal, у которого диаграмма не указывает точность, выбрано (10,2).
- Отдельного rowversion нет. При изменении сравниваются исходные статус, фотограф и время. Все изменения расписания сериализуются транзакцией и sp_getapplock.

Текст до 2.2 и изображение диаграммы не изменены. Различия с таблицей 2.1 объяснены в 2.2. Полностью устранить это расхождение в тексте можно только с разрешения на правку 2.1.

## 5. Реальные проверки SQL Server на Windows

Запустите `windows/VERIFY_SQL_SERVER.bat` под Windows-пользователем с правом создания тестовых баз. Он берёт подключение из `windows/app/appsettings.json`. Рабочую PhotoStudio не удаляет и не очищает: создаёт отдельные базы `PhotoStudio_Verify_*` и `PhotoStudio_UI_*`. В тестах фиксированы часы 08.11.2026 и даты учебных заказов; обычное приложение работает с текущими часами.

Проверяются заполнение, роли, пароль, поиск, тарифы, границы, конфликты залов и фотографов, соседние интервалы, чужие записи, отметка оплаты, устаревшая карточка, фиксация цен, отмена за 24 часа, откат при сбое, отчёт, защита администратора и два независимых процесса. Затем сценарий вводит данные в настоящие формы, нажимает кнопки и сохраняет 12 снимков. При любой ошибке итог считается неуспешным.

Результаты появляются в `windows/evidence-sql`: `test-results.json`, `test-results.md`, `execution.log`, PNG и `screenshots.json`. Для курсовой замените демонстрационные снимки именно снимками из этого прогона и внесите реальные результаты. При сбое журнал покажет причину; не отмечайте такие проверки как пройденные.

`VERIFY_WITHOUT_SERVER.bat` запускает только локальные проверки и демонстрацию форм в памяти. Это отдельная проверка, которая не заменяет серверную.

## 6. Работа с исходным кодом

1. В Visual Studio откройте `PhotoStudio.sln`.
2. Выберите PhotoStudio.Desktop запускаемым проектом.
3. Настройте `src/PhotoStudio.Desktop/appsettings.json` аналогично готовой сборке.
4. Создайте базу указанным выше способом.
5. Нажмите Ctrl+Shift+B для сборки, F5 для запуска. Или откройте BUILD.bat.
6. Исходники разделены на Core (модели, БД, правила), Desktop (9 форм), Verify (проверки). Встроенные шрифт и схемы залов находятся в Assets вместе с лицензией.

Ручная сборка: `dotnet msbuild PhotoStudio.sln -t:Restore,Build -p:Configuration=Release -m:1`.
Серверные проверки из исходников: `dotnet run --project tests/PhotoStudio.Verify -c Release -- evidence-sql`.
Подключение для них также можно передать переменной `PHOTOSTUDIO_TEST_SQLSERVER`; пароли не публикуйте в Git.

## 7. Ошибки и резервная копия

- «Нет подключения»: проверьте запущенную службу SQL Server, имя экземпляра и Windows Authentication в SSMS.
- «Структура отличается»: выбрана база другой версии. Укажите новое имя базы, не удаляйте существующие данные.
- Ошибка сертификата: для локального учебного стенда используется TrustServerCertificate=True. Для сетевой эксплуатации нужен проверяемый сертификат.
- Время занято: поменяйте зал/фотографа или интервал; незавершённые новые заявки тоже занимают время.
- Ошибка NuGet: нужен интернет для восстановления пакетов; готовая сборка SDK не требует.
- После потери связи проверьте, появился ли заказ, прежде чем повторять сохранение.

В SSMS: база → Tasks → Back Up → Full. Укажите доступную серверу папку и сохраните .bak. Проверьте восстановление в отдельную новую базу. Файлы .mdf/.ldf создаёт и обслуживает SQL Server; комплект передаётся SQL-скриптами, а не скопированным рабочим .mdf.

## 8. Репозиторий и сдача

Полный код и локальная история Git включены в комплект. `docs/REQUIREMENTS.md` сопоставляет требования с файлами и проверками. Для публикации под своей учётной записью создайте пустой репозиторий GitHub и подключите его командой `git remote add origin <ваш URL>`, затем `git push -u origin main`. Реальную ссылку внесите в курсовую после публикации. Выдуманная публичная ссылка не подставлялась.

Перед сдачей обязательно выполните SQL-проверки на Windows. Бинарные EXE собраны для Windows x64, но выполнение именно в Windows в среде подготовки не проверялось.
