# Запуск фотостудии на Windows

## Что установить один раз

1. Windows 10/11 x64. Полностью распакуйте архив, например в `C:\Coursework\PhotoStudio`.
2. Установите **SQL Server 2025 Developer** (либо используйте свой SQL Server 2022/2025 Express). На сайте https://www.microsoft.com/en-us/sql-server/sql-server-downloads выберите сервер. В установщике нужны Database Engine Services, Windows Authentication и добавление текущего пользователя в администраторы SQL Server. Сохраните имя экземпляра.
3. SSMS установите с https://learn.microsoft.com/en-us/ssms/install/install . Подключитесь с Windows Authentication. Имя сервера обычно `localhost` или `.\SQLEXPRESS`. Запишите именно имя, с которым подключение прошло.
4. Для редактирования исходников нужна **Visual Studio 2026 Community 18.0 или новее** с компонентом «Разработка классических приложений .NET» и SDK .NET 10. Visual Studio 2022 не поддерживает целевой net10.0 этого проекта. Готовые EXE содержат среду .NET, поэтому для их запуска Visual Studio и SDK не нужны.

## Первый запуск программы

1. Откройте `START_HERE.bat`. Не открывайте файлы внутри ZIP.
2. Если база ещё не настроена, программа покажет окно «Настройка SQL Server». Первое ожидание подключения занимает до 10 секунд.
3. Введите имя сервера из SSMS. Кнопка «Обычный сервер» выбирает localhost; кнопка «SQL Server Express» выбирает `.\SQLEXPRESS`. Если у вас другое имя, впишите его вручную.
4. Имя базы оставьте `PhotoStudio`. Нажмите **«2. Создать / проверить базу и войти»**. Программа создаст базу, 7 таблиц и учебные данные через поставляемый SQL-скрипт. Повторный запуск сохраняет существующие заказы.
5. Дождитесь формы входа. Администратор: **admin**, пароль **PhotoStudio!2026**. Фотограф: **photo1**, клиент: **client1**, пароль тот же.
6. Подключение сохраняется в `%LOCALAPPDATA%\PhotoStudio\connection.json`. Одинаковая настройка используется EXE, проектом в Visual Studio и программой проверок. SQL-пароль в этот файл не сохраняется: мастер использует вход Windows.

Если PhotoStudio уже создана старой версией с другими таблицами, выберите новое имя, например `PhotoStudioER`. Удалять старую базу не требуется. Не нажимайте Reset/Delete в SSMS.

## Открытие кода в Visual Studio

1. Откройте **PhotoStudio.sln**.
2. Если предложено, дождитесь восстановления пакетов NuGet. Для первого восстановления нужен Интернет.
3. В обозревателе решений нажмите правой кнопкой по **PhotoStudio.Desktop** → «Назначить запускаемым проектом».
4. Выберите Debug и Any CPU. Нажмите **F5**.
5. Если базу уже настроили через готовый EXE, Visual Studio подключится к ней с той же настройкой. Иначе заполните окно подключения.
6. Файлы интерфейса находятся в `src\PhotoStudio.Desktop\Views`: `.axaml` — разметка, `.axaml.cs` — обработчики. Основная логика находится в `src\PhotoStudio.Core`, SQL — в `database`.
7. Для визуального предпросмотра XAML можно установить расширение Avalonia для Visual Studio. Для сборки и запуска оно не требуется.

## Проверка на своём компьютере

1. Запустите `windows\VERIFY_SQL_SERVER.bat`. Он использует сохранённый сервер и создаёт отдельные базы с именами PhotoStudio_Verify_* и PhotoStudio_UI_*; рабочую PhotoStudio не изменяет.
2. Дождитесь итоговой строки. Успех — **36 проверок, 0 ошибок**. В том числе проверяются 12 снимков интерфейса, реальная запись заказов и столкновение двух процессов.
3. Результаты и PNG находятся в `windows\evidence-sql`. Если проверка сообщает ошибку, полный текст есть в `execution.log` и `test-results.json`.
4. Для проверки без сервера есть `VERIFY_WITHOUT_SERVER.bat`; её результаты не заменяют серверные.

## Где база данных

Основной способ установки — кнопка создания базы или `database\PhotoStudio_Database.sql` в SSMS. Сервер сам создаёт файлы данных MDF и LDF в своей папке данных. Это полноценная база SQL Server, SQLite не используется.

В `database\backup` дополнительно находится настоящая резервная копия `PhotoStudio_SQLServer2025.bak`, если создание и проверка копии завершились успешно. Она предназначена для SQL Server 2025. Для SQL Server 2022 создавайте базу скриптами: восстановить backup новой версии на старую нельзя. Не обязательно одновременно выполнять и создание скриптом, и восстановление backup.

## Частые ошибки

- **«Сервер не найден»**: SSMS не заменяет сервер. Проверьте SQL Server Configuration Manager / службы Windows и правильность имени экземпляра. Для именованного сервера на другом ПК может требоваться настройка TCP/IP; локальный учебный проект удобнее запускать на том же ПК.
- **«Login failed» / нет права CREATE DATABASE**: войдите в SSMS с Windows Authentication под тем же пользователем. Добавьте его права через администратора SQL Server или попросите администратора заранее создать учебную базу.
- **Ошибка сертификата**: для локального учебного подключения включён TrustServerCertificate. Для рабочей сети требуется сертификат сервера и соответствующая настройка.
- **«SDK .NET 10 не найден» / NETSDK1045**: установите SDK .NET 10 и Visual Studio 2026; затем перезапустите Visual Studio.
- **«Нельзя запустить библиотеку классов»**: назначьте запускаемым проектом PhotoStudio.Desktop, а не Core.
- **Сохранилось старое подключение**: закройте программу и переименуйте `%LOCALAPPDATA%\PhotoStudio\connection.json` в `connection.old.json`. При новом запуске снова появится настройка.
- **«Структура отличается от ER»**: используйте новую пустую базу с новым именем. Схема проекта соответствует исходной ER; другие версии не преобразуются автоматически.

SQL Server Developer/Express устанавливается отдельно с сайта Microsoft: сервер не является частью EXE Avalonia. LocalDB — необязательный вариант SQL Server Express для одного пользователя, доступен отдельной кнопкой; используйте его только при согласовании с преподавателем. Основная инструкция рассчитана на Developer/Express.
